# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's
[private vulnerability reporting](https://github.com/jakeryderv/nba-db/security/advisories/new)
rather than opening a public issue. Reports are reviewed on a best-effort basis; this is a
personal project without a staffed on-call rotation.

Useful details: the affected endpoint or component, the steps to reproduce, and what an attacker
could achieve. If a request is involved, the `X-Request-ID` response header helps correlate it with
service logs.

## Scope

The deployed application at `https://nba-api-production-0cd7.up.railway.app` and the code in this
repository are in scope.

The application is deliberately read-only and exposes no authenticated surface, no user accounts,
and no user-submitted data. In production it connects to PostgreSQL through a SELECT-only database
role, and schema changes and data loads are operator actions run from a trusted machine, never from
CI. Findings that meaningfully affect this posture are the most valuable ones, in particular:

- any path that writes to, alters, or reads beyond the intended data in the production database
- exposure of connection strings, object-storage credentials, or backup contents
- a way to make the public API act as an unintended proxy or amplifier

Out of scope: volumetric denial of service, findings that only affect a local development setup,
missing hardening headers with no demonstrated impact, and reports generated by automated scanners
without a working proof of concept.

## Data

The database contains only publicly available NBA statistics retrieved from the official NBA API.
The dashboard records a small allowlist of anonymous product events and sends no names, search
terms, selections, cookies, or persistent browser identifiers.
